# CMS — Implementation Plan (Teil 2 von 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein Browser-CMS auf GitHub Pages, mit dem das Team ohne Installation die Inhalte statischer PHZH-Seiten (zuerst der OER-Katalog) bearbeitet, direkt in GitHub speichert und ein ZIP für den PH-Server exportiert.

**Architecture:** Statische Vite/React-App ohne eigenen Server. Sie spricht mit der GitHub-REST-API (`api.github.com`) über einen persönlichen fine-grained Token. Jede Seite beschreibt ihre Inhalte in einer `cms.json`; daraus baut das CMS Listen und Formulare über ein Register von Feld-Typen. Speichern = ein Commit über die Git-Data-API (Blobs → Tree → Commit → Ref-Update ohne Force); schlägt das Ref-Update fehl, wird pro Eintrag zusammengeführt. Export = Seiten-Hülle aus Branch `build` + aktueller Stand von `public/content/` aus `main`, im Browser gezippt.

**Tech Stack:** Vite 8, React 18, Vitest + jsdom, DOMPurify, TipTap (`@tiptap/react`, `@tiptap/starter-kit`, `@tiptap/extension-link`, `@tiptap/extension-table` + Row/Cell/Header), `react-easy-crop`, `fflate`. Kein Router, kein Octokit (eigener schlanker `fetch`-Client).

**Spec:** `../oer-dashboard/docs/superpowers/specs/2026-11-26-cms-design.md` (§4, §5.1, §5.3, §5.4, §5.5, §5.6). Teil 1 (statischer Katalog) ist auf `main` von `phzh-zdl/oer-dashboard`; sein Inhaltsformat steht in `oer-dashboard/scripts/lib/toContent.mjs` und `docs/ENTWICKLUNG.md` §4.

## Global Constraints

- Keine Installation beim Team, kein eigener Server; einzige externe Verbindung des CMS: `https://api.github.com` (CSP `connect-src`).
- Alle Abhängigkeiten gebündelt, kein CDN; Schrift MarkWeb lokal (aus `oer-dashboard/src/assets/fonts/` kopieren, Nutzung freigegeben).
- Token: fine-grained PAT, nur „Contents: Read and write" + „Metadata: Read", Organisation `phzh-zdl`. Standard `sessionStorage`, optional „auf diesem Gerät merken" (`localStorage`). Abmelden löscht ihn. **Claude gibt nie selbst einen echten Token ein** — Browser-Tests mit Token macht der User.
- Kein Git-Vokabular in der Oberfläche (kein „Commit", „Merge", „SHA", „Branch", „Pull"). Oberfläche Deutsch.
- Speichern direkt auf `main`, nie Force-Push, nie Branches löschen.
- Bilder: Eingabe nur PNG/JPEG/WebP/GIF (Magic Bytes), max. 5 MB; Ausgabe WebP, Breite max. 800 px, Qualität 0.8, Format 5:3; Warnung unter 640 px Breite; „Ganzes Bild zeigen" = mittig auf Fläche in Fachbereichsfarbe; kein Original speichern; nie SVG.
- Inhaltsdateien schreiben im Format von Teil 1: JSON, 2 Leerzeichen, abschliessender Zeilenumbruch, Feldreihenfolge wie bisher.
- Rich-Text = bereinigtes HTML, Allowlist `p h2 h3 h4 strong em ul ol li a table thead tbody tr th td details summary br`, nur `href` an `a`; Links nur https (safeHttps), `mailto:`, relativ.
- Löschregeln: Fachbereich in Gebrauch → nur mit Umhängen; Format/Zielstufe → aus Ressourcen entfernen (mit Hinweis „wird aus N Ressourcen entfernt"); Lizenz → `license_id: null` (mit Hinweis).
- Barrierefreiheit WCAG 2.1 AA wie `oer-dashboard/docs/BARRIEREFREIHEIT.md` (Labels, Tastatur, Fokus, Kontraste, `--ink-4` nie für Text).
- Entwicklung gegen das Test-Repo `phzh-zdl/cms-test` (Kopie von oer-dashboard, privat), nie gegen echte Inhalte, bis Task 14 abgenommen ist.
- Commits nur nach Go; **Push nie ohne ausdrückliche Bestätigung** (Push macht der User per `! git push`).

## Review Focus

1. **Token abgelaufen oder entzogen während der Arbeit** → beim nächsten Speichern klare Meldung „Ihr Zugangsschlüssel ist abgelaufen oder ungültig", ungespeicherte Änderungen bleiben als Entwurf erhalten. Test: Task 8 (`saveChanges` bei 401 wirft `AuthError`, Entwurf bleibt).
2. **Jemand hat zwischen Öffnen und Speichern dieselbe Datei geändert, aber andere Einträge** → automatisch zusammengeführt, nichts geht verloren, kein Dialog. Test: Task 9 (`mergeCollections` ohne Konflikte).
3. **Tab geschlossen oder Browser abgestürzt vor dem Speichern** → beim nächsten Öffnen wird der Entwurf angeboten. Test: Task 8 (Entwurf in `localStorage`, `loadDraft`).
4. **Export, während noch Ungespeichertes da ist** → Export gesperrt mit Hinweis „Bitte zuerst speichern". Test: Task 12.
5. **Fachbereich löschen, der noch verwendet wird** → Löschen nur nach Auswahl eines Ziel-Fachbereichs; alle Ressourcen werden umgehängt; ohne Auswahl kein Löschen. Test: Task 7.

### Task 2: GitHub-Client

**Files:** Create `src/github/client.js`, `src/github/client.test.js`

**Interfaces:**
- Produces `createClient(token: string, fetchImpl = fetch)` mit Methoden (alle `async`, Basis `https://api.github.com`, Header `Authorization: Bearer <token>`, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`):
  - `getUser() → { login, name }`
  - `listRepos() → { full_name, private }[]` (`GET /user/repos?per_page=100`, Link-Header-Paginierung)
  - `getRef(repo, branch) → sha` (`GET /repos/{repo}/git/ref/heads/{branch}`)
  - `getTree(repo, sha, recursive=true) → { path, type, sha, mode }[]`
  - `getBlob(repo, sha) → Uint8Array` (base64 dekodieren)
  - `getFileText(repo, path, ref) → { text, sha } | null` (404 → `null`; UTF-8 korrekt dekodieren)
  - `createBlob(repo, bytes: Uint8Array) → sha` (base64)
  - `createTree(repo, baseTree, entries: {path, sha|null}[]) → sha` (`sha: null` = Datei löschen)
  - `createCommit(repo, message, tree, parent) → sha`
  - `updateRef(repo, branch, sha) → void` (`force: false`)
  - `listCommits(repo, { path?, perPage=20 }) → { sha, message, author: { name, login }, date }[]`
- Fehler: `GitHubError(status, message)`; Unterklassen `AuthError` (401, sowie 403 mit „Bad credentials"/„expired") und `ConflictError` (422/409 bei `updateRef` „not a fast forward" / „Update is not a fast forward"). Meldungen deutsch.

- [ ] **Step 1: Failing tests** (gemocktes `fetchImpl`): sendet Bearer-Header und API-Version; `getFileText` dekodiert „Grüezi «Zürich»" korrekt aus base64; `getFileText` → `null` bei 404; `listRepos` folgt `Link: <…page=2>; rel="next"`; 401 → `AuthError`; `updateRef` bei 422 „Update is not a fast forward" → `ConflictError`; `createTree` mit `sha: null` sendet `{ path, mode: '100644', type: 'blob', sha: null }`.
- [ ] **Step 2:** Run `npx vitest run src/github` → FAIL.

### Task 9: Konflikte

Vor dem Speichern und beim Öffnen: Hinweis „Diese Seite wurde seit dem Öffnen von <Name> geändert." wenn `getRef` ≠ `headSha` (Name aus `listCommits`).
